# Data provenance

## Runtime assets

The current viewer does **not** use the earlier Vanatome browser-optimized atlas.

It loads the following male anatomy assets from the pinned Anatria3D anatomy dataset:

- `skeletal_male.glb`
- `muscular_male.glb`
- `cardiovascular_male.glb`
- `manifest.json`

Pinned upstream commit:

`949ac80cc9763539afc48e60b5246132f00468db`

The male source atlas contains 3,478 structures across all systems. This web application currently renders the three systems above.

## Provenance

BodyParts3D → Z-Anatomy → Anatria3D GLB adaptation.

The upstream GLB pipeline documents baked Blender modifiers, Draco position/normal quantisation, viewer-side material replacement, stable organ identifiers, and hierarchy export. It states that no polygon reduction is applied beyond Draco quantisation.

## Nomenclature

The manifest exposes Terminologia Anatomica 2 Latin and clinical English. These professional labels are used directly by the interface.

## Scope and validation

The geometry is not generated by AI. The site preserves source structure identifiers and does not invent missing structures.

Automated tests cover viewer interaction logic, not anatomical truth. Anatomical accuracy ultimately inherits the limitations and curation of the upstream open datasets. The site must therefore not be described as a validated diagnostic, radiology, or surgical-navigation system.
